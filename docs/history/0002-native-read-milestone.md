# 0002 — First native milestone

Date: 2026-10-10, America/Sao_Paulo. Status: implemented and validated locally.

## Request and decisions

Create a MoobFS image and a native module that mounts on Linux and reads two
independent files with shared physical content. Record the construction and create
continuity rules for Codex, Claude and Cursor. ADRs 0001–0003 document the
scope; M1 is read-only and separate from the original transactional proposal.
The user confirmed GPL-2.0-only for the whole project.

## Implementation

- `include/` and `common/`: little-endian format, CRC32C, SHA-256 and a shared
  parser with validation of bounds, padding, names and references.
- `tools/`: deterministic offline creation with deduplication by byte equality
  and refusal to overwrite; JSON verifier without repairs.
- `kernel/`: VFS/iomap module, separate inodes, reads, flat directory,
  FIEMAP, read-only and full validation at mount.
- `tests/` and `vm/`: tools and an isolated QEMU VM, Debian kernel
  `6.12.111+deb13-amd64`, package `6.12.111-1`. The module is not loaded on the host
  nor in the Docker Desktop kernel. Docker provides tools to start the VM.
- `docs/format-m1.md`: specification of the implemented format.

## Evidence executed

- `make test`: 9 tests on macOS arm64; the same tests passed on Linux.
- `make test BUILD=build/asan CFLAGS='-O1 -g -fsanitize=address,undefined -fno-omit-frame-pointer' LDFLAGS='-fsanitize=address,undefined'`:
  9 tests passed on macOS, without sanitizer diagnostics.
- `make vm-test`: module build and real execution on Linux x86-64 passed.
  GCC 14.2.0, QEMU 10.0.13; Debian base image pinned by digest in the Dockerfile.
- FIEMAP: inodes **2 and 3**, both link count 1, same physical offset **12288**,
  extent **16384** bytes and SHARED flag. Logical content: 12562 bytes.
- Verified full read, pread in parts, read crossing a page, seek,
  EOF, directory enumeration/rewind, missing file, rejection of write,
  create, remove, rw mount and rw remount, unmount and new mount.
- Empty, one-byte and 64 KiB objects; 15 malformed images rejected by the
  tools and by the module. No BUG/Oops/WARNING observed in the log.
- Reproducible SHA-256 of the shared image:
  `6bbb9b0b08d4bfda24c3a7dbd9708792e1e3ce96807cad49ac83d9bfeac7c5cc`.

Console, versions, kernel configuration, image and module stay in `build/vm/`,
regenerated by the command. We version scripts and summary, not the binaries.

## Attempts and fixes

The initial setup looked for `loop.ko`, but Debian ships `loop.ko.xz`;
the harness now decompresses it. The first rw mount check used
BusyBox, which retries in ro mode. The mount already worked; the false
positive in the test was fixed by using `mount(2)` and requiring `EROFS`. The later
full run passed. Names were limited to printable ASCII and the suite
was repeated after that change.

## Limitations and continuity

The kernel used does not enable KASAN or PROVE_LOCKING; we do not claim validation with
those features. Auxiliary apt dependencies are not all pinned; we do not promise a
fully bit-for-bit build. We did not measure gains in latency, memory or usefulness
for LLMs. There are no writes nor transactional durability. Next work:
consolidate the open source base, documentation and CI before writes and recovery.
