# 0046 — KASAN workflow Python dependencies pinned by hash

Date: 2026-10-12. Branch: `ci/pin-virtme-ng`, from `origin/main` (`1b87764`). Status:
implemented; the first real run with hashes is that of the KASAN workflow on this PR.

## Goal

Resolve the only Pinned-Dependencies finding of the OpenSSF Scorecard (alert 1, score 8): in
`.github/workflows/kasan.yml`, the `pip install` pinned only the version of `virtme-ng`
(`virtme-ng==1.41`), and its dependencies were left without a version and without a hash. Numbering: 0046,
the first free number according to the Q2 queue session (which uses 0035 to 0038 and 0042 to 0044); `origin/main`
and the remote branches were checked.

## Decision

Install from `vm/kasan-requirements.txt`, generated by `pip-compile --generate-hashes`
(pip-tools 7.4.1, Python 3.12, the Ubuntu 24.04 version of the runners), with
`pip install --require-hashes`. The file pins `virtme-ng` 1.41 and the six resolved
dependencies (`argcomplete` 3.7.2, `certifi` 2026.7.22, `charset-normalizer` 3.5.2, `idna` 3.20,
`requests` 2.34.2, `urllib3` 2.8.0), with the hashes of all published distributions, and carries
in its header the command to regenerate it. The `VIRTME_NG_VERSION` variable was removed from the workflow, so
that the version has a single source.

The file lives in `vm/` because it belongs to the harness. This changes nothing in the trigger: `vm/**` and
`kasan.yml` itself already trigger KASAN.

## Changes

- New `vm/kasan-requirements.txt` (with SPDX).
- `.github/workflows/kasan.yml`: `pip install --user --require-hashes -r
  vm/kasan-requirements.txt`; `VIRTME_NG_VERSION` removed.
- `docs/development.md`: the local KASAN step uses the same file.
- `CHANGELOG.md` and `docs/history/README.md`.

No file of the Q2 queue (`vm/suite.sh`, `bench/load.c`) was touched, as the Q2 session
requested.

## Evidence

- `pip-compile` in a `python:3.12-slim` (amd64) container generated the file.
- In an amd64 `ubuntu:24.04` container with `python3-pip` from apt,
  `python3 -m pip install --user --require-hashes -r vm/kasan-requirements.txt` installed the seven
  distributions and `vng --version` answered `virtme-ng 1.41`. The container needed
  `PIP_BREAK_SYSTEM_PACKAGES=1` (PEP 668); the GitHub runner already accepted `--user` without it,
  as the previous runs of the workflow show. If the runner starts refusing, the fix is the
  same variable in the step.
- The kernel build and the suite under KASAN were not executed locally; they run on the PR.

## Limitations

- The dependency versions are frozen; an update requires regenerating the file.
  Dependabot does not track this file, because it is outside a directory configured for
  `pip`.
